01

结论先行

判断 01

联动是赠品，不是卖点

厂商发布会的主叙事是拍摄、翻译、支付、提词；家居控制只在参数表末尾出现。用户真正为它买单的理由里，「控家电」排不进前三。

判断 02

只有三家做成了产品

小米、华为、千问把联动做进了系统；雷鸟靠社区插件、Rokid 靠 SDK 让开发者自己写；INMO、魅族、海信没有可验证的家居联动。

判断 03

全部停在 L1

三家都只做到「语音遥控」——和音箱、手机助手是同一件事，只是麦克风长在脸上。真正的「看见设备再动作」只有千问做了两个点。

第四个判断，也是这份调研最想说的：三星不该在中国打「控制」，该打「看懂」。原因很硬——小米 AIoT 已连接 11.61 亿台设备、米家月活 1.24 亿；华为鸿蒙智家连接 1.82 亿台；天猫精灵覆盖 4000 万家庭。三星手机在中国没有存量优势，SmartThings 的中国区可用性连第三方评测都写着「需要确认」。在这种局面下做「用眼镜开关灯」，是用自己的短板去打别人的城墙。

但有一件事三家都没做：看见一台不认识的家电，认出型号，给出操作或报修路径。这条路不依赖账号体系、不挑品牌、不需要网关，恰好是摄像头 + 多模态模型最擅长的事。这也是第 10 节 POC 的由来。

一句话：国内厂商把眼镜做成了「随身语音入口」，三星的机会是把它做成「随身视觉入口」——不是替代小爱/小艺，而是站在它们管不到的地方。

另有两股「家」的力量不在眼镜生态里，但决定了场景上限：海尔（1 亿+ 互联设备、6600+ 生态资源、AI 之眼 2.0、AgentOS / 小优）与美的（2026-03 全屋智能战略：一张家电网络、一个聪明大脑、一个开放平台，家庭智能体「小美」）。它们目前没有眼镜入口，但家电侧已经能主动服务——这是眼镜厂商最可能的合作方，也是最可能的对手。

标准层：Matter 与中国版「OneConnect」同时在推进

Matter 1.6

NFC「触碰即配」、Joint Fabric 多控制端共管、温控器建议功能、设备可上报自身能力极限、传感器支持历史状态时间点。它解决「能不能连」，不解决「好不好用」。

《智家统一互联标准》

2026-03 由 GIIC 联合中国家用电器研究院及海尔、美的、华为等七巨头发布，定义发现、配网、接入认证与控制接口。刚起步，别指望它现在就能让眼镜跨品牌。

一个被忽略的事实：Matter 只统一底层通信。灯的开关、调光、色温能跨生态，但「呼吸灯」「音乐律动」这类高级能力仍要回原厂 App。这意味着眼镜即使接上 Matter，也只拿到设备能力的「公共子集」。

小米 AI 眼镜

官方联动 · L1
产品2025-06 发布；40g；8.6 小时；1200 万像素 / 2K 视频；五麦阵列 + 骨传导；高通 AR1 + 索尼传感器；国补价 1699 元

联动方式眼镜 → 手机小爱 → 米家云。需登录同一小米账号；与音箱 / 电视同处一室时，语音唤醒优先走音箱或电视，要用眼镜需单指长按或轻声唤醒

华为官网「小艺语音技能」页面明确列出「语音控制智能家居」，并给出「打开客厅的灯」示例——这是六家里证据最硬的一条。家侧能力更强：小艺管家 6.0 支持声纹识人、3D 方位控灯（「说哪亮哪」），但这是家庭主机 + 传感器的能力，不经过眼镜。

官方联动 · L1 向 L2 探
产品2026H1 线上份额 8.6%，拍摄眼镜细分 23.3% 第一；阿里生态打通淘宝、高德、支付宝、夸克网盘；五麦阵列含骨传导，「你好千问」唤醒
联动对象天猫精灵全屋智能体系内已接入的智能家电；场景可跨到儿童房设备、屏屏对讲、日历提醒
联动方式云云对接：眼镜通过云端与全屋智能系统对接，用户在 App 授权家庭权限即可，无需额外加装网关、不改原有布线
能做到把眼镜做成继中控屏、面板、传感器之后的第四类交互入口；不在家也能「提前开回家模式」「确认门窗状态」；「叫宝宝起床」同时触发儿童房设备 + 屏屏对讲 + 日历提醒
视觉延伸厂商口径：扫描冰箱内食材推荐菜谱；记不清物品位置时借眼镜回溯线索；日用品耗尽语音复购；孩子作业错题现场讲解
做不到仍是体系内设备；强依赖云端与家庭授权；视觉能力目前是单点场景，没有形成「任意设备 → 识别 → 操作」的通用链路

2026-07-08 建博会首次公开「人·家·生活」框架，随后全屋版功能上线。这是六家里唯一把「眼镜 = 随身入口」写成战略叙事的厂商，也是唯一公开描述 L2 视觉家居场景的厂商。注意：视觉部分来自厂商宣传材料，未见独立实测。

雷鸟创新

无官方联动 · 社区补位
产品2026H1 线上份额第一（18.9%，AR 品类 28.5%）；雷鸟 iO：34g（前框 17g）、双目显示、提词 / 翻译，2499 元（国补后 1996 元起），2026-08-21 发布
联动对象官方：无家居联动。社区：个人二开插件支持「米家控制」
联动方式开发者插件（非官方能力、无 SLA、随版本可能失效）；RayNeo AI App 已上架鸿蒙原生版，但上架的是录音 / 通知 / 提词 / 实时字幕 / AI 问答等功能，不是家居控制
能做到证明「开放 SDK 能长出场景」——社区插件还带导航、巡航、电子书、番茄钟、天气、热搜、自有知识库
做不到普通用户买不到「官方支持的家居控制」；没有账号级授权、没有设备语义、没有跨品牌

这条最值得注意：它说明家居联动不是「技术做不到」，而是「厂商没把它当主线」。雷鸟把资源压在光学全链路自控与轻量化上，软件是补课项——鸿蒙原生 App 上架被媒体形容为「软件补课才走一半」。

Rokid 乐奇

无官方联动 · SDK 自建
产品2026H1 线上份额 16.7%；Rokid Glasses 主打实时翻译、AI 问答、AR 导航；YodaOS-Sprite（2026-06 发布）；支持千问、豆包、Gemini、ChatGPT、DeepSeek 多模型切换
联动对象官方：无家居联动。开发者：可通过 CXR-L / CXR-S / 裸机开发访问图像、音频、显示、指令通道，自建任意家居 App
联动方式SDK + AIUI Studio（在线 IDE、免真机调试、一键发布）；3 万+ 开发者、5000+ 合作项目；已打通支付宝与微信支付
能做到「把眼镜当一个 Android 设备来写」——理论上任何有开放 API 的家居平台都能接
做不到能力在开发者手里，不在产品里；没有官方家居入口；项目制成活，C 端用户无感

Rokid 的路线是「做平台不做场景」：把 IO 与系统能力开放，让生态自己长。好处是想象力大，坏处是家居这种需要授权、设备语义、长期维护的场景，开发者很难独立扛。

联动能力四层模型

用同一把尺子量所有厂商，避免被发布会话术带走
L0
无联动眼镜是独立设备，和能力中心不发生关系
INMO / 魅族 / 海信
L1
语音遥控说指令 → 助手 → 云端 → 设备；本质是「把音箱搬到脸上」
小米 / 华为 / 千问
L2
视觉理解看见设备 / 食材 / 物品，结合画面给服务，而不只是执行指令
千问（单点：冰箱、找物）
L3
空间与主动知道人在哪、设备在哪、状态如何，无需开口即触发
眼镜侧：无人做到
关键错位：「家」这一侧已经跑到 L2 / L3——华为 AI 超感传感器做到人来灯亮、风避人吹、跌倒识别；海尔 AI 之眼 2.0 与 AgentOS 能主动做健康看护、烹饪引导、能源优化；美的「小美」做家庭智能体。但这些能力都不经过眼镜。眼镜侧仍停在 L1，中间缺的正是「人的位置与意图」这根线。

这也是为什么「眼镜 + 家居」的故事听起来很美、用起来很平：家已经会自己思考了，眼镜只是又多了一个遥控器。

06

四条技术路径

同样是「能控灯」，底下是四套完全不同的工程
路径代表链路优点代价
账号内闭环小米 / 华为 眼镜 → 手机助手 → 厂商云 → 设备；同一账号、同一品牌手机 延迟最低、权限清晰、离线场景可兜底（华为 PLC 本地可控） 生态封闭；换手机品牌即失效；第三方设备进不来
云云对接千问 眼镜云 → 全屋智能云 → 设备；App 授权家庭权限 接入快、无需网关、不改布线、不挑手机品牌 依赖云与授权；断网不可用；跨云排障困难
SDK 自建Rokid / 雷鸟（社区） 开发者写 App → 调眼镜 IO → 调家居开放 API 最灵活；可做深度定制与 B 端项目 无官方 SLA；授权、语义、维护全得自己扛；C 端不可预期
Matter / 桥接涂鸦 Super Bridge → SmartThings / Apple / Alexa 非 Matter 设备（Wi-Fi / Zigbee / BLE / PLC）→ 桥 → Matter 生态 跨品牌、跨协议；一次桥接多生态可用 只覆盖基础能力；高级功能回原厂 App；目前没有眼镜厂商用它
端侧直连无产品化案例 眼镜 BLE / Thread 直连设备，不经云 低延迟、隐私最好、断网可用 配网难、协议栈重、眼镜功耗与天线空间不够
第四条是被低估的路。涂鸦的 Super Bridge 已能把非 Matter 设备一键桥到苹果、三星、亚马逊。如果三星要做「在中国也能控家电」的眼镜，这是唯一不依赖米家 / 鸿蒙 / 天猫精灵开放后台的技术路径——代价是只拿到 Matter 的公共能力子集。

真实瓶颈

对三星的启示

Galaxy Glasses + SmartThings 在中国该怎么站

先把事实摆清

形态音频眼镜，无屏
影像12MP IMX681，带自动对焦
重量 / 续航约 50g / 155mAh·9h
价格379–499 美元
平台Android XR（Jetpack Projected）
上市2026 秋季，分市场
SmartThingsMatter 1.5 摄像头首家
中国可用性待确认（第三方评测原话）
不要假设两件事：① 用户会用三星手机（中国市场份额低）；② SmartThings 在中国能直接控到主流家电（设备兼容清单未确认）。这两条任一不成立，「眼镜控家电」的链路就断了。

三条判断

不要打「控制」
小米 11.61 亿设备、华为 1.82 亿、天猫精灵 4000 万家庭，且全部免费。三星拿不到米家 / 鸿蒙 / 天猫精灵的深度授权，做出来的控制只覆盖少数 Matter 设备，体验必然更差。更致命的是：Galaxy Glasses 没有屏幕，控制结果只能靠语音确认——这恰恰是 L1 体验最弱的一环。
要打「看懂」
摄像头 + 多模态度模型是三星的真实优势（12MP 自动对焦，对近距离铭牌 / 故障码比定焦方案更有用）。而「看一台不认识的家电 → 认型号 → 给操作或报修」这条路不依赖任何生态授权，也不挑用户用什么手机。它是三家大厂都没做的格子。
用「合作」代替「对抗」
家电侧的主动智能已经很强（海尔 AI 之眼 2.0、美的小美、华为 AI 超感），缺的是「人在现场的第一视角」。三星可以把自己定位成这些家的视觉外设，而不是另一个控制中心。对国内家电厂商来说，这是增量；对三星来说，这是唯一能绕开生态封锁的入口。

三个可打方向

方向做什么为什么是三星风险
A · 家电「看一眼」
建议 POC		 扫铭牌 / 故障码 / 面板 → 识别品牌型号 → 给操作步骤或报修入口；不认识就要求重拍，不硬猜 不依赖账号与生态；12MP 自动对焦；Gemini 视觉 + 本地 OCR + 知识库 RAG 全是现成能力 型号库冷启动；跨品牌资料版权；识别错了要能兜底
B · 家的巡检 第一视角走一圈，识别漏水、插座过载、燃气、宠物异常，生成巡检报告 家侧 AI 强在「传感器覆盖处」，弱在「人眼能看到但传感器没装的地方」 责任边界（报错了算谁的）；隐私（拍到家人）
C · Matter 的人侧入口 涂鸦 Super Bridge 把国内设备桥到 SmartThings，眼镜做语音 + 视觉入口 唯一不依赖米家 / 鸿蒙 / 天猫精灵后台的跨品牌路径 只拿到 Matter 公共能力；SmartThings 中国可用性未定；数据出境

A 是「能力已就绪、风险最低」；B 是「差异化最强、责任最重」；C 是「战略正确、落地最慢」。如果只有四周，做 A。

10

POC 建议：家电「看一眼」

4 周、2.5 人月，不与任何生态为敌

场景：用户家里空调不制冷，面板显示一个不认识的代码。他戴上眼镜说「看看这个」——眼镜拍下面板，耳中回应：「这是格力的 E5，过滤网堵塞或室外机散热不良。先拆滤网冲洗，还不行我帮你报修。」他不知道型号也没关系，眼镜看铭牌就认出来了。整个过程没有打开任何一个 App，没有登录任何账号。

W1 · 型号与故障码识别
采集 200 台主流家电的铭牌 / 面板 / 故障码样本（自有 + 公开数据集）；用 Gemini 3.5 Flash 视觉 + 本地 OCR 双通道；建立「品牌—品类—型号—故障码」映射表。验收：Top-1 型号识别 ≥ 80%。
W2 · 知识库与拒答
按「故障码」而非文档切 chunk；混合检索（BM25 + 向量）；每条答案强制带出处（手册页码 / 厂商公告）；检索不到就返回「这个型号我没查到，建议报修」，禁止模型自造步骤。
W3 · 眼镜端链路
ProjectedContext 取佩戴态；语音触发抓帧；质量门（模糊 / 反光 / 主体占比）；置信度三档分流；无屏播报规范（一句一动作，≤15 字）；失败重拍最多 3 次后转人工。
W4 · 10 人实测 + 评审演示
真实家庭环境、真实故障（或模拟故障）；记录识别准确率、一次解决率、平均耗时、用户是否愿意再用；同步准备 3 分钟现场演示脚本。
